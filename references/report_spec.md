# 报告规范（客户视角，交付前逐句自检）

## 文件
- 命名：`<客户名>核验报告_<年季度>.html`（如 `张玺核验报告_2026Q3.html`），放工作目录根，用 present_files 推送。
- 样式：朴素正式——微软雅黑、白底黑字、表格细线（Table Grid 风），仅 绿=通过 / 红=不符 / 橙=待确认 三种语义色。**禁**深色卡片、艺术字、装饰图标（李总版式铁律对 HTML 同样适用）。

## 结构（六段）
1. **标题 + 核验元信息**：核验时间、范围（N 位讲师 N 条记录）、核验维度四项（时长/费用/可访问性/人脸）。
2. **总体结论表**：核验通过（含人脸确认）/ 汇总金额不符 / 无人脸画面 / 待人工，各类条数 + 一句话说明。
3. **金额问题（重点）**：勾稽差额单独成段，列小计→待人工项→合计→表内汇总→差额。
4. **费率口径提示**：算术对但口径存疑的记录，逐条说明。
5. **逐条核验明细表**：日期/类型/主题/申报课时/视频实测/授课费/时长判定/费用校验/人脸核验（N/8 帧本人）。底部加类型说明脚注（专场 vs 栏目切片）。
6. **人脸核验结果** + **下一步**：结果分档统计、边界说明；下一步用"事项 | 责任方"两列表（客户方事项写具体动作，我方事项写"登录态已就绪，随时可跑"）。

## 交付纪律（李总铁律，违反即返工）
- 全文客户视角：不出现备课说明、内部提醒、口语化自评、讲师视角编排注。
- 每个数字带口径与来源；查不到就写"待确认"，绝不编造。
- 判定动词统一：`满足/正确/确认本人出镜`（绿）、`不符/异常`（红）、`待确认/待人工/无法核验`（橙）。
- 核验边界必须如实写明（抽样帧数、无法核验的情形），不给客户"100% 全验"的错觉。
